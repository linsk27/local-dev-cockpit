# Dev Cockpit 0.1.10

这一版继续补强真实项目兼容性，重点解决 monorepo 扫描和终端排查 Python 环境的问题。

## Highlights

- 修复 Node monorepo 根目录阻断扫描的问题。
- 识别 `pnpm-workspace.yaml`、`turbo.json`、`nx.json`、`lerna.json`、`rush.json` 这类工作区根标记。
- 遇到 monorepo 根目录时，会继续扫描 `apps`、`packages`、`services`、`frontend`、`backend` 等子目录，避免只显示根目录而漏掉真正可运行的前后端项目。
- `npx local-dev-cockpit doctor <项目路径>` 现在会为 Python 项目列出检测到的环境候选，包括 `.venv`、父级工作区虚拟环境、编辑器配置、`environment.yml` 和 Conda 环境。
- README 补充了 monorepo 扫描和终端排查 Python/Conda 环境的说明。

## 使用建议

如果一个仓库是 `apps/web` + `packages/api` 这类结构，建议把仓库根目录作为 Dev Cockpit 工作区。0.1.10 会保留根目录项目，同时继续发现子项目。

如果 Python 项目在别人电脑上缺依赖，先运行：

```bash
npx local-dev-cockpit doctor D:\path\to\project
```

它会显示当前命令解析结果和可选 Python 环境。桌面版用户可以把候选里的 `conda:环境名` 或 `python.exe` 路径填到项目详情的“运行环境”区域。

## Verification

- `pnpm release:check`
- `npx local-dev-cockpit doctor fixtures\projects\flask-api`
- `node packages\cli\dist\index.js scan fixtures\projects`
- Node workspace root fixture: package root + `pnpm-workspace.yaml` + `turbo.json` + child web/api projects
