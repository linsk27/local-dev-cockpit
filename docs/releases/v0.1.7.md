# Dev Cockpit 0.1.7

这版补齐“别人不用 VS Code，而是在终端里激活 Conda/venv 后跑项目”的场景。

## 修复内容

- 从已激活终端启动 Dev Cockpit 时，会继承 `CONDA_PREFIX` / `CONDA_DEFAULT_ENV` / `VIRTUAL_ENV`。
- Python 命令会在没有更明确项目环境时使用当前终端环境里的 `python.exe`，减少 `ModuleNotFoundError` 这类“终端能跑，面板里缺包”的问题。
- 启动前诊断也会识别继承来的终端环境，不再误报“Python 项目依赖环境未固定”。
- README 和架构文档补充了 Conda/venv 识别优先级，以及桌面双击无法读取其他终端激活状态的边界。

## 使用建议

如果项目依赖只装在某个 Conda 环境里，可以这样启动：

```powershell
conda activate your-env
npx local-dev-cockpit
```

桌面安装版适合长期使用，但它不能读取另一个终端窗口的 `conda activate` 状态。桌面版用户更推荐在项目里保留 `.venv` / `.conda` / `environment.yml` / `.vscode/settings.json`，让 Dev Cockpit 能稳定识别环境。

## 验证

- `pnpm --filter @local-dev-cockpit/server test`
- `pnpm --filter @local-dev-cockpit/server typecheck`
