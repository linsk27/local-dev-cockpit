# Dev Cockpit 0.1.2

这是一次真实项目启动可靠性版本，重点减少“别人下载后命令跑不起来但不知道为什么”的问题。

## 主要变化

- 启动前预检 Node 依赖：有 `package.json` 依赖但没有 `node_modules` 时，提前提示 `npm install` / `pnpm install`。
- 启动前预检 Python 环境：有 `requirements.txt` / `pyproject.toml` 但没有 `.venv`、`venv`、`.conda` 或 Conda `environment.yml` 时，提示会回退系统 Python。
- 新增 Java 可移植性提示：Maven / Gradle 项目没有 `mvnw` / `gradlew` wrapper 时，提示依赖用户本机运行时。
- 新增 PHP 依赖提示：检测到 `composer.json` 但没有 `vendor/autoload.php` 时，提示先 `composer install`。
- 新增 Ruby 依赖提示：检测到 `Gemfile` 但没有 `Gemfile.lock` 时，提示先 `bundle install` 并提交锁文件。
- 新增 .NET restore 提示：检测到 .NET 项目但没有 `obj/project.assets.json` 时，提示先 `dotnet restore`。
- 失败日志解释增强：Python 缺包、Node 缺包、Node 脚本命令缺失、相对模块缺失会转成可执行建议。
- README 同步说明启动前预检和失败后解释策略。

## Windows Desktop

下载 `Dev-Cockpit-0.1.2-win-x64.exe` 后可直接运行。当前仍是未签名 portable 版本，Windows 可能提示未知发布者。

## 已知限制

- Dev Cockpit 只做检测和提示，不会自动修改用户项目环境。
- 缺少依赖时仍需要用户在对应项目目录手动执行 install / restore。
- 桌面版尚未代码签名。
