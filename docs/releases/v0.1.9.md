# Dev Cockpit 0.1.9

这版重点处理真实用户电脑上的两个问题：检查更新失败不可读、Python/Conda 环境缺包时不知道该怎么修。

## Highlights

- 检查更新从单一 GitHub API 改为双通道：GitHub Release 失败后，会用 npm registry 获取最新版本号。
- npm 兜底成功时，仍会给出标准安装包和免安装版的 GitHub Release 下载地址。
- 两个更新源都失败时，错误会明确说明网络、代理、证书或限流方向，并保留手动 Release 入口。
- Python `ModuleNotFoundError` 的失败摘要会直接提示 Conda 项目如何绑定环境，或如何从已激活终端启动 Dev Cockpit。
- README 补充了“什么时候需要配置 Python 环境”和“检查更新为什么可能失败”的说明。

## 使用建议

如果别人电脑的设置页显示“无法连接 GitHub Releases”，先确认浏览器能否打开 GitHub。如果浏览器能打开但应用里失败，通常是 Electron/Node 进程没有继承浏览器代理。0.1.9 会自动尝试 npm registry；如果 npm 可访问，就能继续判断最新版并显示下载入口。

Python/Conda 项目如果终端能跑、Dev Cockpit 缺包，优先在项目详情的“运行环境”区域选择 Conda 候选，或者填写 `conda:环境名`。如果使用 `npx` 版本，也可以先 `conda activate 环境名`，再从同一个终端执行 `npx local-dev-cockpit`。

## Windows Desktop

推荐下载 `Dev-Cockpit-Setup-0.1.9-win-x64.exe`。它是标准安装向导，适合日常使用；已安装旧版本时会直接覆盖升级。

免安装版是 `Dev-Cockpit-0.1.9-win-x64.exe`，适合临时试用。替换前请先关闭正在运行的旧 exe。

当前产物仍未代码签名，Windows 可能提示未知发布者。
